# Zotero 内容导入协议

## 目的

本协议用于将已验证的内容文件（尤其是带本地图片资源的 Markdown）纳入 Zotero，并使父条目、附件、元数据与本地预览保持可验证的一致性。目标 collection、来源平台和主题筛选标准均由当前任务决定，不在本协议中预设。

## 1. 预检与边界

1. 明确本次要处理的文件、目标 collection、可复用条目的判定键和允许的元数据来源。
2. 只处理存在、非空且已通过来源工作流验证的文件；不要为抓取失败或不支持的来源创建不完整附件。
3. 写入前检查 Zotero Local API 是否可用，以及当前任务是否明确授权创建条目、上传附件、修改元数据或移动旧附件到 Trash。
4. Local API 授权密钥仅保存在运行进程内；不得写入配置、报告或日志。

## 2. 父条目与类型

- 使用规范化的来源 URL 作为跨批次去重键；先检索整个 Zotero library，再创建新父条目。
- 对命中的已有条目，默认保留已有元数据，只增量加入目标 collection 和/或补充经过明确授权的附件。
- 根据资源的实际出版形态选择 item type。常见映射：
  - 独立博客/专栏文章：`blogPost`
  - 论坛、问答线程中的具体发言：`forumPost`
  - 无法更精确归类的一般页面：`webpage`
- 不得按域名或 collection 一刀切迁移 item type；类型迁移应有明确的来源形态依据。

## 3. Markdown 附件与图片资源

1. 将 Markdown 作为 `text/markdown`、`imported_file` 子附件导入。
2. Markdown 使用相对图片路径时，只复制该文件实际引用的本地资源到 Markdown 附件所在 Zotero storage 目录的同名相对位置。例如 `assets/example.jpg` 应位于 `<attachment-storage>/assets/example.jpg`。
3. 复制前解析并校验路径：来源资源必须位于任务明确提供的资源根目录，目标必须仍位于该附件的 storage 目录内。
4. 只复制缺失或内容不一致的文件；不批量复制无引用资源。
5. 跨设备同步后，应抽样重新打开带图 Markdown，确认当前 Zotero 同步配置保留 sidecar 图片文件。

## 4. 元数据补全

可自动写入的字段必须来自可验证的来源数据，例如规范标题、作者、发布时间、语言和站点/容器名称。

- 写入前保留来源字段与解析规则的记录。
- 不凭推断填充作者、日期、摘要、访问日期或主题标签。
- 仅在任务明确要求时覆盖已有元数据；已有条目默认采取补充而非替换策略。
- 摘要和主题标签通常需要人工语义判断；正文已作为附件保留时，不应机械复制全文到摘要。

## 5. 清理旧附件

只有在新的 Markdown 附件及其引用资源已验证后，才可处理冗余快照或旧文件。

- 删除操作必须获得明确授权。
- 使用 Zotero Trash（可恢复），不要硬删除。
- 删除前按附件 MIME 类型、文件名和父条目核对目标，避免误删 PDF、笔记或其他有价值附件。

## 6. 完成验证与交付

至少验证：

- 父条目 URL、类型与 collection 归属；
- Markdown 附件的父子关系、`imported_file` 模式、`text/markdown` MIME 类型和文件可访问性；
- 每个相对图片引用均存在于预期的附件 storage 路径；
- 元数据写入后的实际回读结果；
- 被移入 Trash 的附件数量及键列表（如执行了清理）。

交付时报告处理范围、创建/复用的条目数、附件数、图片资源数、失败项和未验证风险。使用机器可读报告保存每条记录的来源 URL、父条目键、附件键和验证状态。
